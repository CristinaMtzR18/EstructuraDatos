Gestión de Memoria y Listas Enlazadas en C++ (Enfoque POO)

1. Memoria en C++: Stack vs Heap y Apuntadores

Teoría (C++ según Deitel): La memoria se divide en dos segmentos: el Stack (pila) gestiona variables locales de forma automática y rápida, pero con tamaño limitado. El Heap (montículo) permite solicitar memoria manualmente durante la ejecución para estructuras que cambian de tamaño. Para manipular el Heap, C++ utiliza apuntadores (variables que almacenan direcciones de memoria).

Stack

Ejemplo en código (Incidente Crítico):

#include <iostream>
#include <string>

class SesionPAD {
public:
    std::string usuario;
    SesionPAD(std::string u) : usuario(u) {}
};

int main() {
    // Asignación estática (Stack)
    SesionPAD sesionLocal("Usuario Fijo"); 

    // Asignación dinámica con apuntador (Heap)
    SesionPAD* sesionDinamica = new SesionPAD("Hana chan"); 
    
    std::cout << "Sesion en Heap: " << sesionDinamica->usuario << std::endl;
    delete sesionDinamica; // Siempre liberar la memoria
    return 0;
}

Explicación: Creamos la clase SesionPAD. Instanciamos sesionLocal directamente en el Stack (se libera sola al terminar). Luego, usamos un apuntador y el operador new para crear a sesionDinamica en el Heap. El operador -> nos permite acceder a su atributo. Finalmente, liberamos la memoria manualmente con delete.

🍰 De la vida cotidiana: El Stack es el espacio fijo de la barra de tu cocina; es rápido, pero no crece. El Heap es como rentar una bodega externa enorme: usas el espacio que necesites para tus pasteles, pero eres responsable de vaciarla (liberar memoria) al terminar.

2. Gestión de Memoria Dinámica (new y delete)

Teoría (C++ según Deitel): En C clásico se usaba malloc y free. Deitel enseña que C++ introduce los operadores seguros new (que reserva memoria e invoca constructores) y delete. Olvidar liberar esta memoria provoca "fugas de memoria" (memory leaks).

Sesion_PAD

Ejemplo en código (Incidente Crítico):

#include <iostream>

int main() {
    int cantidad_turnos;
    std::cout << "¿Cuántos usuarios llegaron al módulo?: ";
    std::cin >> cantidad_turnos;

    // new[] sustituye a calloc/malloc
    int* turnos = new int[cantidad_turnos]; 

    for(int i = 0; i < cantidad_turnos; i++) {
        turnos[i] = 1000 + i; 
    }

    // delete[] sustituye a free, previniendo fugas de memoria
    delete[] turnos; 
    return 0;
}

Explicación: Le preguntamos al usuario el tamaño en tiempo de ejecución. Usamos new int[cantidad_turnos] para reservar dinámicamente el arreglo en el Heap. Al final, utilizamos delete[] (con corchetes por ser arreglo) para devolver la memoria.

🍰 De la vida cotidiana: Usar new es como rentar un molde gigante para un pastel de bodas. Usar delete es lavar ese molde y devolverlo a la tienda. Si nunca lo devuelves (fuga de memoria), la tienda se quedará sin moldes.

3. Listas Enlazadas Simples

Teoría (C++ según Deitel): Una lista enlazada es una estructura dinámica de nodos. Cada nodo encapsula un dato y un apuntador al siguiente nodo. Esto permite que la estructura crezca dinámicamente sin requerir memoria contigua.

N1
N2
N3

Ejemplo en código (Incidente Crítico):

#include <iostream>
#include <string>

class Nodo {
public:
    std::string tramite;
    Nodo* siguiente; 
    Nodo(std::string t) : tramite(t), siguiente(nullptr) {}
};

class ListaSesiones {
private:
    Nodo* cabeza;
public:
    ListaSesiones() : cabeza(nullptr) {}

    void insertar(std::string tramite) {
        Nodo* nuevo = new Nodo(tramite);
        nuevo->siguiente = cabeza; 
        cabeza = nuevo;
    }
};

Explicación: Creamos la clase Nodo que guarda el trámite y el apuntador siguiente inicializado en nullptr. La clase ListaSesiones protege la cabeza. El método insertar() crea un nodo en el Heap y lo enlaza al inicio de la cadena.

🍰 De la vida cotidiana: Como una búsqueda del tesoro. Tienes la primera pista (la cabeza) y esa pista te dice exactamente a qué coordenada ir para encontrar la siguiente pista, sin tenerlas todas juntas.

4. Listas Doblemente Enlazadas

Teoría (C++ según Deitel): Cada nodo contiene dos apuntadores: uno al nodo siguiente y otro al anterior. Esto permite el recorrido bidireccional (revisar el historial hacia adelante y hacia atrás sin reiniciar).

N1
N2
N3

Ejemplo en código (Incidente Crítico):

#include <iostream>
#include <string>

class NodoDoble {
public:
    std::string usuario;
    NodoDoble* siguiente;
    NodoDoble* anterior;
    
    NodoDoble(std::string u) : usuario(u), siguiente(nullptr), anterior(nullptr) {}
};

int main() {
    NodoDoble* usr1 = new NodoDoble("Estudiante A");
    NodoDoble* usr2 = new NodoDoble("Adulto Mayor B");

    usr1->siguiente = usr2;
    usr2->anterior = usr1; // Enlace bidireccional

    delete usr1; delete usr2;
    return 0;
}

Explicación: Definimos NodoDoble agregando el apuntador anterior. Enlazamos el siguiente de usr1 hacia usr2, y mágicamente enlazamos el anterior de usr2 de regreso a usr1.

🍰 De la vida cotidiana: Es como los vagones de un tren. Si estás en el vagón comedor, puedes abrir la puerta delantera para ir al vagón de pasajeros (siguiente), pero también tienes una puerta trasera para regresar al vagón de equipaje (anterior).

5. Pilas y Colas Dinámicas (Modularización)

Teoría (C++ según Deitel): Aprovechando la memoria dinámica, construimos Pilas y Colas sin tamaño fijo. C++ fomenta la Modularización separando el código en archivos .h (declaraciones/contratos) y .cpp (implementación lógica).

.h
.cpp

Ejemplo en código (Incidente Crítico):

// --- Archivo: ColaPAD.h (Declaración Modular) ---
#include <string>

struct NodoCola {
    std::string tramite;
    NodoCola* siguiente;
};

class ColaDinamica {
private:
    NodoCola* frente;
    NodoCola* final;
public:
    ColaDinamica();
    void encolar(std::string t); 
    void desencolar();           
};

// --- Archivo: ColaPAD.cpp (Implementación) ---
#include <iostream>
// #include "ColaPAD.h"

ColaDinamica::ColaDinamica() : frente(nullptr), final(nullptr) {}

void ColaDinamica::encolar(std::string t) {
    NodoCola* nuevo = new NodoCola{t, nullptr};
    if (!final) frente = final = nuevo; 
    else {
        final->siguiente = nuevo; 
        final = nuevo;
    }
}

Explicación: Demostramos la modularización separando el .h y el .cpp. La clase ColaDinamica encapsula los apuntadores. El método encolar() respeta el principio FIFO agregando nodos exclusivamente en la posición final.

🍰 De la vida cotidiana: Crear archivos modulares es como un menú de restaurante. El archivo .h es el menú que ve el cliente (solo sabe los nombres de los platillos). El archivo .cpp es la cocina oculta (donde el chef implementa toda la receta).
